# 学生状态规则 v1.1

## 两个独立维度

`baseline_status` 表示基线诊断进度，`skill_state` 表示已有学习证据支持的能力水平。两者不得混用，也不得通过默认值互相推导。

### baseline_status

- `unknown`：尚无足够诊断或学习证据。此时不得创建任何 `skill_state` 记录。
- `in_progress`：已有真实诊断或学习事件，但基线证据尚未完整。只有被真实事件覆盖的能力才可写入 `skill_state`。
- `established`：基线诊断已经形成足够证据；各能力状态仍必须分别由其学习事件支持。

学生档案初始化时，`baseline_status` 必须为 `unknown`。未测试不等于能力未建立，绝对不能初始化为 `S0`。

### skill_state

以下定义直接采用既有研究报告中的项目内部状态体系：

- `S0`：未建立。
- `S1`：提示后理解。
- `S2`：能模仿完成。
- `S3`：熟悉任务可独立。
- `S4`：陌生材料可迁移。
- `S5`：延迟复测仍稳定。
- `S6`：能解释方法、适用条件和边界，并跨情境迁移。

来源：`docs/research/北京语文小初高贯通完整能力研究 V1.1：补章、补字段、补证据与 SKILL 落地.pdf` 第 8 页。

## 写入规则

1. 创建 `skill_state` 前必须至少存在一条同时匹配 `student_id` 与 `ability_id` 的真实 `learning_event`。
2. `evidence_count` 必须大于或等于 1，并与可追溯证据一致。
3. `baseline_status = unknown` 时不得存在任何 `skill_state`。
4. H4 以上提示后完成不能作为完全独立证据。
5. `S3` 升至 `S4` 必须有陌生材料迁移证据。
6. `S4` 升至 `S5` 必须有延迟复测证据。
7. 主能力和子技能状态分别记录，不得用主能力状态覆盖子技能差异。

## 隐私规则

- 学生主键必须是 `STU-` 开头的假名化 `student_id`，不得使用真实姓名。
- 身份映射表不得进入研究报告、能力主数据、Skill 示例或普通知识库。
- `logs/` 不得记录学生敏感正文。
