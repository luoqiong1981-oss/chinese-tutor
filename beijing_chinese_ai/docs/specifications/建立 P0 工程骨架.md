====================
一、当前已经冻结的设计
====================

1. 系统采用：
本地主库 + ChatGPT Project 工作台 + beijing-chinese-tutor SKILL

2. 能力体系固定为：
8 个操作领域 + 1 个跨领域模块，共 39 项能力。

领域代码：
BA
LU
RD
CL
PO
WR
OC
MC
WB

其中：
BA/LU/RD/CL/PO/WR/OC/MC
architecture_type = operational_domain

WB
architecture_type = cross_domain_module

3. 39 个能力 ID 为永久主键，不允许重新编号、回收或改变含义。

能力数量必须严格为 39：

BA01—BA04
LU01—LU04
RD01—RD08
CL01—CL04
PO01—PO04
WR01—WR06
OC01—OC03
MC01—MC03
WB01—WB03

4. baseline_status 与 skill_state 必须严格分离。

初始状态：

baseline_status = unknown

绝对不能因为“还没测试”就写成：

skill_state = S0

S0—S6 只能在真实训练或诊断产生证据后写入。

5. 学生数据不得直接以真实姓名作为数据库主键。
统一使用假名化 student_id。

6. 当前不要开发：
- Web 前端
- App
- 登录系统
- 大模型聊天 UI
- 自动生成大量训练题
- 推荐系统
- 向量数据库
- RAG
- 数据可视化 Dashboard

先把数据底座建正确。

====================
三、各目录职责
====================

docs/research/
保存已经完成的政策、考试、课程标准、小初高贯通等研究成果。

docs/specifications/
保存系统蓝图、数据字典、版本规范、能力模型工程规范。

docs/acceptance/
保存 P0/P1 等验收标准和验收报告。

data/master/
系统主数据。
以后存放：
- 39 项能力表
- 子技能表
- 证据来源表
- 核心结论映射
等稳定数据。

data/students/
学生长期学情数据。

data/tasks/
诊断题、训练题、迁移题等任务库。

data/sessions/
每次真实辅导产生的 session 记录。

data/examples/
只保存用于 Schema 和程序测试的匿名示例数据。

schemas/
JSON Schema 数据契约。

后续至少包括：
- ability_catalog.schema.json
- subskills.schema.json
- evidence_sources.schema.json
- claims.schema.json

scripts/
数据验证、迁移、索引、检查脚本。

后续核心脚本：
scripts/validate_v1_1.py

tests/
自动化测试。

skills/beijing-chinese-tutor/
后续放置正式辅导 SKILL。

logs/
程序运行、数据校验和版本迁移日志。
不得存放学生敏感正文。
